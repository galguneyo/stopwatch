# 서울 ↔ 제주 직항 항공권 실시간 확인 에이전트

서울-제주 국내선 직항 항공권을 지정된 요일/시간대 조건으로 매주 확인하고,
공휴일·샌드위치 데이 등 수요 집중일을 표시하는 대시보드용 파이프라인입니다.

## 먼저 읽어주세요 — 가장 중요한 제약사항

**대한민국에는 국내선 항공권의 실시간 판매가·좌석을 공개적으로 제공하는 API가
없습니다.** (2026-09-15 기준 확인: `data.go.kr`의 국토교통부/한국공항공사 공공API는
"운항 스케줄" 정보만 제공하며, 실시간 판매 가격·잔여좌석 API는 존재하지 않습니다.)

실질적으로 실시간 가격을 얻는 방법은 두 가지뿐입니다.

1. **GDS/NDC 상용 계약** (Amadeus, Sabre, Travelport, 또는 각 항공사 자체 API) — 별도 계약과 비용 필요.
2. **각 항공사 공식 예매 화면을 브라우저 자동화로 조회** — 이 프로젝트가 택한 방식.

2번 방식은 항공사들이 reCAPTCHA 등 봇 차단을 적용하고 있어(WebSearch로 확인),
화면 구조 변경/차단에 따라 주기적인 유지보수가 필요하고, 클라우드 IP(GitHub
Actions 등)에서 차단될 가능성도 있습니다. 또한 이 코드를 작성한 개발 세션 자체가
일반 인터넷 접근이 정책적으로 차단된 샌드박스였기 때문에, **실항공사 사이트의
CSS 셀렉터 값은 실제로 접속해 검증하지 못했습니다.** `config/selectors.yaml`의
모든 항공사가 `verified: false`로 비어 있는 이유입니다 — 확인되지 않은 값을 채워
넣어 "작동하는 것처럼" 보이게 하지 않았습니다.

**즉, 지금 이 저장소를 그대로 실행하면 목업(mock) 데이터만 나옵니다.** 실데이터로
전환하려면 아래 [실데이터 연결하기](#실데이터-연결하기)를 따라 인터넷이 되는
환경에서 셀렉터를 채워야 합니다.

## 구현된 검색 규칙

| 항목 | 규칙 |
|---|---|
| 노선 | 서울(GMP, 일부 LCC는 ICN) ↔ 제주(CJU), **직항만** |
| 항공사 우선순위 | 대한항공(KE) → 아시아나(OZ) → 제주항공(7C) → 티웨이(TW) → 에어부산(BX) → 에어서울(RS) → 이스타(ZE) |
| 서울 출발(제주 도착) | 금요일 10:00 이후 출발, **또는** 토요일 오전(00:00~11:59) 출발 |
| 제주 출발(서울 도착) | 일요일 18:00 이후 도착, **또는** 월요일 전체 |
| 조회 주기 | 매주 1회 (GitHub Actions cron), 향후 8주(~2개월)치 후보일 재계산 |
| 수요 집중일 표시 | 공휴일, 샌드위치 데이(휴일 사이에 낀 평일), 3일 이상 연휴를 배지로 표시 |

날짜/시간 판정 로직은 `src/rules.py`에 있으며 네트워크 의존성이 전혀 없어
`tests/test_rules.py`로 전부 검증됩니다 (2026년 실제 공휴일 달력 기준).

```bash
cd flight-tracker
pip install -r requirements.txt
python -m pytest tests/ -v
```

## 아키텍처

```
flight-tracker/
├── src/
│   ├── holidays_2026.py       # 2026년 공휴일 데이터 (출처: 다수 언론 교차확인, README 하단 참고)
│   ├── rules.py                # 요일/시간/공휴일/샌드위치데이 판정 (순수 함수, 테스트 완료)
│   ├── scan.py                 # 오케스트레이터: 후보일 생성 → provider 조회 → data/results.json 저장
│   └── providers/
│       ├── base.py             # FlightOffer, Provider 공통 인터페이스
│       ├── mock_provider.py    # 목업 데이터 생성기 (source="mock"으로 명시)
│       └── playwright_provider.py  # 실항공사 조회용 범용 엔진 (셀렉터 검증 전엔 의도적으로 실패)
├── config/selectors.yaml       # 항공사별 CSS 셀렉터 설정 (현재 전부 미검증)
├── data/results.json           # scan.py 실행 결과 (대시보드가 읽음)
├── dashboard/index.html        # 정적 대시보드: 월별 달력형 예약가능현황 + 상세 목록
├── src/weekly_report.py        # 주차별 사전예약 확인 마크다운 리포트 생성 (reports/latest.md)
├── tests/test_rules.py
└── .github/workflows/flight-scan.yml  # 주간 자동 실행 (repo 루트 기준 경로)
```

`scan.py`는 `providers.base.FlightSearchProvider` 인터페이스에만 의존하므로,
목업 → 실데이터 전환 시 `--provider live` 플래그만 바꾸면 됩니다. 특정 항공사의
셀렉터가 아직 검증되지 않았다면 해당 항공사/날짜는 조용히 건너뛰지 않고
`skipped` 목록에 사유와 함께 기록되며, 대시보드는 이를 빨간 경고 배너로 보여줍니다.
**실데이터가 없을 때 목업으로 자동 대체하지 않습니다** — 실제 가격인지 아닌지
사용자가 항상 명확히 알 수 있도록 하기 위함입니다.

## 로컬 실행

```bash
cd flight-tracker
pip install -r requirements.txt

# 1) 목업 데이터로 파이프라인/대시보드 확인 (네트워크 불필요)
python src/scan.py --provider mock --weeks-ahead 8

# 2) 주차별 사전예약 확인 리포트 생성 (reports/latest.md)
python src/weekly_report.py

# 3) 정적 서버로 대시보드 열기
python -m http.server 8000
# 브라우저에서 http://localhost:8000/dashboard/index.html
```

대시보드는 두 파트로 구성됩니다.
- **월별 예약가능현황**(달력형): 노선별로 검색 대상 요일(서울→제주는 금/토, 제주→서울은
  일/월)만 색이 채워지고, 나머지 요일은 흐리게 표시됩니다. 셀 안에는 최저가와 편수를,
  테두리 색으로 공휴일(빨강)/샌드위치 데이(주황)/3일 이상 연휴(파랑)를 표시합니다.
- **상세 목록**: 날짜별 전 항공편(항공사·시각·가격·매진 여부)을 카드로 나열합니다.

`weekly_report.py`는 같은 데이터를 ISO 주차 단위로 묶어 "이번 주에 예약해야 할 편"을
사람이 바로 읽을 수 있는 마크다운으로 정리합니다 — 수요 집중 주차는 상단에
경고 문구가 자동으로 붙습니다.

## 실데이터 연결하기

1. 인터넷이 열려 있는 환경(본인 PC 등)에서 대한항공/아시아나 등 국내선
   예매 검색 결과 화면을 서울↔제주, 편도, 직항 조건으로 연다.
2. 개발자도구(F12)로 결과 행/시각/가격/매진 표시 요소의 CSS 셀렉터를 확인한다.
3. `config/selectors.yaml`에서 해당 항공사 값을 채우고 `verified: true`로 바꾼다.
4. `playwright install chromium` 실행 후 `python src/scan.py --provider live` 로 검증.
5. 항공사 사이트 이용약관(자동화 조회 관련 조항)을 반드시 확인하고, 요청 빈도를
   낮게 유지해 서비스에 부담을 주지 않도록 한다.

## GitHub Actions 자동화

`.github/workflows/flight-scan.yml`이 매주 월요일 09:00(KST)에 `scan.py`를
실행하고 `data/results.json`을 커밋합니다. GitHub 호스팅 러너는 이 개발 세션과
달리 일반 인터넷 접근이 가능하므로, 셀렉터가 검증된 이후에는 이 워크플로만으로
매주 자동 갱신이 가능합니다. 아직 검증 전이라도 워크플로 자체는 안전하게
0건 + skipped 사유를 기록하며 실패하지 않습니다.

## 2026년 공휴일 데이터 출처

`src/holidays_2026.py`의 날짜는 2026-09-15 시점 언론 보도(한국경제, 위키트리,
KKday, wegive, trip.com 등)를 다중 교차 확인하고, 요일을 그레고리력으로 재계산해
보도 내용과 일치함을 검증한 것입니다. 정부 공식 관보 고시를 직접 조회할 수
있는 네트워크가 이 개발 환경에서는 차단되어 있었기 때문입니다. 운영 전
`data.go.kr`의 특일 정보 API 등으로 최종 재확인을 권장합니다.
