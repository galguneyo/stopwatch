# 갈매기의 귀향 플래너 — 서울 ↔ 제주 직항 항공권 확인 에이전트

서울-제주 국내선 직항 항공권을 지정된 요일/시간대 조건으로 매주 확인하고,
공휴일·샌드위치 데이 등 수요 집중일을 함께 표시하는 대시보드 파이프라인입니다.

## 현재 상태 한눈에 보기

| 영역 | 상태 | 근거 |
|---|---|---|
| 요일·시간대·공휴일 판정 로직 | **완성** (단위테스트 8개 통과) | `src/rules.py`, `tests/` |
| 대시보드 (Travel Planner UI) | **완성** | `dashboard/index.html` |
| 주차별 사전예약 리포트 | **완성** | `src/weekly_report.py` |
| 날씨 실데이터 | **실연결 검증 완료 · 매일 자동 갱신** | [VERIFICATION.md](VERIFICATION.md) |
| 당일 지연·결항 | 코드 완성 · **서비스 키만 발급하면 자동화 가능** | [VERIFICATION.md](VERIFICATION.md) |
| 항공권 실데이터 | **미연결** — 항공사가 클라우드 IP를 차단 | [VERIFICATION.md](VERIFICATION.md) |

즉 **항공권·지연은 목업(mock), 날씨는 실데이터**로 동작합니다. 대시보드 상단
배너가 매번 어느 쪽이 실데이터인지 명시하므로 둘을 혼동할 일은 없습니다.

지연 정보의 출처인 공공데이터포털은 항공사와 달리 클라우드에서 차단되지 않는
것을 실측으로 확인했습니다. 서비스 키만 발급받아 `KAC_SERVICE_KEY` Secret으로
등록하면 `delay-scan.yml`이 매일 실데이터를 갱신합니다.

## 구매 제안 — 무엇을 근거로 말하는가

`src/insights.py`가 관측 이력(`data/history.jsonl`)에서 네 가지를 계산해
`data/insights.json`으로 내보내고, 대시보드는 이를 "지금 챙겨야 할 날짜" 카드와
"이 날짜 진단" 패널로 보여줍니다.

| 지표 | 계산 방식 | 필요한 관측 |
|---|---|---|
| 가격 지수 | 같은 조회 구간 다른 후보일들의 최저가 중앙값 대비 | 1회 |
| 가격 추세 | 최저가가 첫 관측 대비 몇 % 움직였는지 | 2회 이상 |
| 변동 폭 | 최저가의 (최대−최소)/최소 | 3회 이상 |
| 매진 속도 | 예약 가능 편수의 하루 감소분, 이 속도면 언제 동나는지 | 2회 이상 |

여기에 공휴일·샌드위치 데이·연휴 여부(달력에서 확정적으로 나오는 값)를 더해
긴급도를 매기고 **지금 예약 / 주시 / 여유**로 판정합니다.

**원칙: 관측하지 않은 것은 근거로 쓰지 않습니다.** 화면의 모든 근거 문구는 실제로
계산한 수치에서만 나옵니다. 이력이 모자라면 추세를 추정하지 않고 "관측 N회 —
추세는 데이터가 쌓인 뒤"라고 밝힙니다. "작년에는 4주 전부터 올랐다" 같은, 이
저장소가 관측한 적 없는 이야기는 만들어내지 않습니다. 매진 시점도 최근 감소
속도를 그대로 이은 단순 선형 추정임을 화면에 함께 적습니다.

이력은 스캔을 돌릴 때마다 한 줄씩 쌓입니다. 목업으로 화면을 확인할 때는
`--backfill N`으로 과거 관측을 합성할 수 있습니다(목업 전용, 합성값임을 명시).

```bash
python src/scan.py --provider mock --weeks-ahead 8 --backfill 5
```

## 예매 링크

펼친 시간표에서 **출발 시각을 누르면 해당 항공사 예매 화면이 새 탭에서 열립니다.**
링크는 `config/booking_links.yaml`에서 관리합니다.

- `entry_url` — 항공사 예매 진입 페이지. 지금은 여기로 연결됩니다.
- `deep_link` — 노선·날짜가 채워진 검색 결과 URL 템플릿. 비어 있습니다.

딥링크를 비워둔 이유는 셀렉터와 같습니다. 각 사의 딥링크 규격을 이 환경에서
확인할 수 없었고(샌드박스는 물론 Actions 러너에서도 항공사 도메인이 403),
추측한 주소를 넣으면 클릭했을 때 깨진 페이지로 보내게 됩니다. 그건 링크가 없는
것보다 나쁩니다. 그래서 지금은 "진입 페이지로 보내되, 날짜는 직접 선택해야
한다"고 화면에 명시합니다.

브라우저에서 검색을 한 번 해보고 주소창을 복사해 치환자
(`{origin}` `{dest}` `{date}` `{date_dash}`)로 바꾼 뒤 `verified: true`로
바꾸면, 그 항공사부터 곧바로 딥링크로 전환되고 안내 문구도 함께 바뀝니다.

## 갱신 주기 — 10분 원칙과 한 가지 예외

| 대상 | 주기 | 근거 |
|---|---|---|
| 대시보드 화면 | **10분** | `dashboard/index.html`이 자동 재조회. 탭이 백그라운드면 멈추고, 돌아올 때 오래됐으면 즉시 갱신 |
| 날씨 (`weather-scan.yml`) | **10분** | Open-Meteo는 무료·키 불필요. 공항 3곳 × 10분 = 하루 432회로 무료 한도(1만) 내 |
| 지연·결항 (`delay-scan.yml`) | **10분** | 실시간성이 가장 큰 값. 키 미등록 시 첫 단계에서 즉시 종료 |
| 항공권 (`flight-scan.yml`) | 주 1회 | **예외** — 아래 참고 |

항공권만 10분 주기에서 제외했습니다. 항공사 공식 예매 화면을 10분마다 조회하는
것은 상대 서비스에 부담을 주고 차단을 자초하는 행위라 요금과 무관하게 적절하지
않고, 항공권 가격이 분 단위로 변하지도 않기 때문입니다.

화면 상단의 갱신 표시를 누르면 주기와 상관없이 즉시 다시 불러옵니다. 갱신에
실패하면 화면을 비우지 않고 직전 데이터를 유지한 채 "갱신 실패"로 표시합니다 —
오래된 값을 최신인 것처럼 보여주지 않기 위해서입니다.

## 왜 항공권만 목업인가

**대한민국에는 국내선 항공권의 실시간 판매가·좌석을 공개 제공하는 API가
없습니다.** (2026-09-15 확인: `data.go.kr`의 국토교통부/한국공항공사 공공API는
"운항 스케줄"만 제공하고, 실시간 판매가·잔여좌석 API는 없습니다.)

실질적인 선택지는 둘뿐입니다.

1. **GDS/NDC 상용 계약** (Amadeus, Sabre, Travelport, 또는 항공사 자체 API) — 계약·비용 필요
2. **각 항공사 예매 화면을 브라우저 자동화로 조회** — 이 프로젝트가 택한 방식

2번을 실제로 시험해봤습니다. GitHub Actions 러너에서 돌린 결과
(`src/verify_live.py`, run `34944953393`), **대한항공과 아시아나는 연결 자체가
끊기고**(`ERR_HTTP2_PROTOCOL_ERROR` / 403), 티웨이는 `Access Denied`, 제주항공도
브라우저 접근 시 403이었습니다. 에어부산만 정상 로드됐습니다.

이것은 셀렉터 문제가 아니라 **접속 출처(IP) 차단**입니다. 셀렉터를 정확히 채워도
클라우드에서는 1·2순위 항공사를 가져올 수 없으므로, 수집은 가정용 IP(개인 PC)에서
실행해야 합니다. 절차는 [VERIFICATION.md](VERIFICATION.md)에 정리했습니다.

그래서 `config/selectors.yaml`의 모든 항공사는 `verified: false`로 비어 있습니다 —
확인되지 않은 값을 채워 넣어 "작동하는 것처럼" 보이게 하지 않았습니다. 검증 전에는
`playwright_provider.py`가 의도적으로 실패하므로, 추측값으로 가짜 데이터가 만들어질
일이 없습니다.

## 구현된 검색 규칙

| 항목 | 규칙 |
|---|---|
| 노선 | 서울(GMP, 일부 LCC는 ICN) ↔ 제주(CJU), **직항만** |
| 항공사 우선순위 | 대한항공(KE) → 아시아나(OZ) → 제주항공(7C) → 티웨이(TW) → 에어부산(BX) → 에어서울(RS) → 이스타(ZE) |
| 서울 출발(제주 도착) | 금요일 10:00 이후 출발, **또는** 토요일 오전(00:00~11:59) 출발 |
| 제주 출발(서울 도착) | 일요일 18:00 이후 도착, **또는** 월요일 전체 |
| 조회 주기 | 매주 1회 (GitHub Actions cron), 향후 8주(~2개월)치 후보일 재계산 |
| 수요 집중일 표시 | 공휴일, 샌드위치 데이(휴일 사이에 낀 평일), 3일 이상 연휴를 배지로 표시 |

날짜/시간 판정 로직은 `src/rules.py`에 있으며 네트워크 의존성이 전혀 없어
`tests/test_rules.py`로 전부 검증됩니다 (2026년 실제 공휴일 달력 기준).

```bash
cd flight-tracker
pip install -r requirements.txt
python -m pytest tests/ -v
```

`scan.py`는 `providers.base.FlightSearchProvider` 인터페이스에만 의존하므로,
목업 → 실데이터 전환 시 `--provider live` 플래그만 바꾸면 됩니다. 특정 항공사의
셀렉터가 아직 검증되지 않았다면 해당 항공사/날짜는 조용히 건너뛰지 않고
`skipped` 목록에 사유와 함께 기록되며, 대시보드는 이를 빨간 경고 배너로 보여줍니다.
**실데이터가 없을 때 목업으로 자동 대체하지 않습니다** — 실제 가격인지 아닌지
사용자가 항상 명확히 알 수 있도록 하기 위함입니다.

## 로컬 실행

```bash
cd flight-tracker
pip install -r requirements.txt

# 1) 목업 데이터로 파이프라인/대시보드 확인 (네트워크 불필요)
python src/scan.py --provider mock --weeks-ahead 8

# 2) 주차별 사전예약 확인 리포트 생성 (reports/latest.md)
python src/weekly_report.py

# 3) 날씨 목업 데이터 생성 (네트워크 불필요)
python src/weather_scan.py --provider mock

# 4) 정적 서버로 대시보드 열기
python -m http.server 8000
# 브라우저에서 http://localhost:8000/dashboard/index.html
```

### 대시보드 (Travel Planner 스타일)

한 번에 펼쳐지는 달력이 아니라, 화면 하나에서 아래 순서로 좁혀가는 방식입니다.

1. **노선 토글**(서울→제주 / 제주→서울) — Apple 세그먼트 컨트롤 스타일.
2. **날짜 스트립**: 검색 대상 요일(서울→제주는 금/토, 제주→서울은 일/월)만 가로
   스크롤 칩으로 나열, 공휴일(빨강 점)/샌드위치 데이(주황 점)/연휴(파랑 점) 표시.
3. **날씨 요약**: 선택한 날짜의 출발/도착 공항 예보(요약·강수확률·풍속)를 상단에
   표시. 날짜를 바꾸면 즉시 갱신됩니다. 예보는 통상 신뢰 구간인 약 14일까지만
   제공되며, 그 밖의 날짜는 "예보 범위 밖"으로 명시됩니다(없는 값을 지어내지 않음).
4. **항공사 목록**: 항공사 배지(색상 모노그램 — 실제 공식 로고 이미지가 아니라
   구분용 색상 배지입니다. 공식 로고 파일을 확보하면 `.badge`에 `<img>`로 손쉽게
   교체 가능)와 함께, 선택한 날짜·시간대 조건 안에 예약 가능한 편이 있는지를
   신호등(초록=있음/주황=적음/빨강=매진/회색=운항없음)으로 보여줍니다.
5. 항공사 행을 클릭하면 **그날 전체 시간대**의 시간·좌석상태·이코노미가·비즈니스가를
   표로 펼쳐 보여줍니다. 요청하신 시간대 밖의 편은 흐리게 표시되고 안내 문구가 붙습니다.

`weekly_report.py`는 같은 데이터를 ISO 주차 단위로 묶어 "이번 주에 예약해야 할 편"을
사람이 바로 읽을 수 있는 마크다운으로 정리합니다 — 수요 집중 주차는 상단에
경고 문구가 자동으로 붙습니다.

### 날씨 데이터에 대한 같은 원칙

항공권과 마찬가지로 이 세션에는 날씨 API(Open-Meteo 등)에 접속할 네트워크가
없어 `providers/weather.py`의 `OpenMeteoWeatherProvider`는 실행 검증을 하지
못했습니다. Open-Meteo는 API 키가 필요 없는 공개 API라 셀렉터처럼 막힐 일은
없지만, 그래도 "이 세션에서 직접 실행해보지 못했다"는 사실은 동일하므로
네트워크가 열린 환경에서 먼저 하루치로 확인해보길 권장합니다.

## 실데이터 연결하기

1. 인터넷이 열려 있는 환경(본인 PC 등)에서 대한항공/아시아나 등 국내선
   예매 검색 결과 화면을 서울↔제주, 편도, 직항 조건으로 연다.
2. 개발자도구(F12)로 결과 행/시각/가격/매진 표시 요소의 CSS 셀렉터를 확인한다.
3. `config/selectors.yaml`에서 해당 항공사 값을 채우고 `verified: true`로 바꾼다.
4. `playwright install chromium` 실행 후 `python src/scan.py --provider live` 로 검증.
5. 항공사 사이트 이용약관(자동화 조회 관련 조항)을 반드시 확인하고, 요청 빈도를
   낮게 유지해 서비스에 부담을 주지 않도록 한다.

## GitHub Actions 자동화

`.github/workflows/flight-scan.yml`이 매주 월요일 09:00(KST)에 `scan.py`를
실행하고 `data/results.json`을 커밋합니다. GitHub 호스팅 러너는 이 개발 세션과
달리 일반 인터넷 접근이 가능하므로, 셀렉터가 검증된 이후에는 이 워크플로만으로
매주 자동 갱신이 가능합니다. 아직 검증 전이라도 워크플로 자체는 안전하게
0건 + skipped 사유를 기록하며 실패하지 않습니다.

## 2026년 공휴일 데이터 출처

`src/holidays_2026.py`의 날짜는 2026-09-15 시점 언론 보도(한국경제, 위키트리,
KKday, wegive, trip.com 등)를 다중 교차 확인하고, 요일을 그레고리력으로 재계산해
보도 내용과 일치함을 검증한 것입니다. 정부 공식 관보 고시를 직접 조회할 수
있는 네트워크가 이 개발 환경에서는 차단되어 있었기 때문입니다. 운영 전
`data.go.kr`의 특일 정보 API 등으로 최종 재확인을 권장합니다.
